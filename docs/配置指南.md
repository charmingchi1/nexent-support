### 0.1 环境值集中存放：config.json

本指南与 README 已做**个人数据脱敏**：姓名、open_id、应用 ID、Windows 用户名路径、代理端口等一律不出现，以 `<占位符>` 或「见 config.json」代替。环境值模板与真实值分两个文件：

| 文件 | 内容 | 用途 |
|------|------|------|
| `config.json` | 本机实际值（person 个人信息 / proxy 代理 / paths 路径 / links 文档链接 / ids 表 ID / automation 定时） | 本机查阅与换机对照；**含个人信息，不入库、勿直接外传** |
| `config.example.json` | 同结构脱敏模板，个人字段为 `<占位符>`，links/ids 为团队共用值已填好 | 新人起步模板（已随仓库入库）；外传时用它替换 config.json |

改环境（换机、换代理端口、资源链接变更）时先改 `config.json`，再同步工作区 `scripts\sync\sync-config.json` 与自动化 prompt 中的路径（三者关系见 §3.1、§4.2）。

## 1. 代码仓（Git）配置

### 1.1 克隆与分支

```bash
git clone https://github.com/ModelEngine-Group/nexent.git "D:/projects/feishu/nexent"
cd "D:/projects/feishu/nexent"
git checkout develop
git branch --set-upstream-to=origin/develop develop
```

- 仓库：https://github.com/ModelEngine-Group/nexent （公网 GitHub，无需内网权限）
- 分支：**develop**（与远端 origin/develop 建立跟踪关系，同步脚本才能自动拉取）
- 当前 HEAD 以每日同步后 `tmp_base/资源索引.md` 的「nexent 代码仓」行为准（含最新 commit 与本次拉取数）

⚠️ **只用 `D:\projects\feishu\nexent`**。上级目录 `D:\projects\nexent` 是旧副本，检索会命中过时逻辑，勿用（2026-10-12 用户确认）。不确定时先问用户。

### 1.2 用途与日常更新

- 用途：按报错关键字 / 接口路径 / 日志特征检索源码，定位责任模块（定性判定树 Q2）；
- 日常更新不需要手动 git——每日 08:30 自动化的 **git 阶段**会 `fetch` + `pull --ff-only`（只快进，不产生合并提交）；
- 手动更新：`git -C "D:/projects/feishu/nexent" pull --ff-only`；
- 若 `--ff-only` 报错（本地有游离改动），先 `git stash` 或确认后 `git reset --hard origin/develop`，再重拉。

### 1.3 网络与代理（如需）

克隆/拉取慢或超时时，为本机 Git 配置代理。**端口查 `config.json` → `proxy`**（占位 `<代理端口>`）：

```bash
git config --global http.proxy  http://127.0.0.1:<代理端口>
git config --global https.proxy http://127.0.0.1:<代理端口>   # 不用时 --unset 解除
```

## 2. 飞书 CLI（lark-cli）安装与配置

### 2.1 安装

```bash
npm install -g @larksuite/cli
lark-cli --version        # 当前 1.0.97，低于此版本建议升级
```

安装位置（npm 全局）：`%APPDATA%\npm\node_modules\@larksuite\cli\scripts\run.js`。
同步脚本会按「环境变量 `LARK_CLI_ENTRY` → `sync-config.json` 的 `lark_cli_entry` → 默认 npm 路径」顺序定位入口。**Windows 下脚本用 node 直调该 run.js**（spawn `.cmd` 会被新版权限策略拒绝），所以换机后若 npm 全局路径变了，必须同步改 `sync-config.json` 的 `lark_cli_entry`。

### 2.2 应用与首次授权（OAuth）

- 无需自建应用 App ID：`lark-cli auth login` 为 Device Flow 扫码授权（默认按全部 domain 申请 scopes，覆盖支撑所需能力）；授权人姓名与 open_id 记录于 `config.json` → `person`，`lark-cli auth status` 可实时查看；
- agent 平台会话内也可运行 `/lark-cli:setup`，按指引安装/建 profile/扫码。

### 2.3 身份与授权有效期

- 双身份：**user**（读写文档/表格、代发需单独授权）+ **bot**（应用身份），`defaultAs: auto` 自动选择；
- user access token 当天有效，**refresh token 约 7 天**（如 10-21 授权则 10-28 过期）；
- ⚠️ **超过 7 天不使用任何 lark-cli 命令，授权会整体失效**——每日自动化的飞书同步会失败并在 `tmp_base/资源索引.md` 标红，这是最常见的故障，重新 `lark-cli auth login` 扫码即可，无需重装。

### 2.4 常用检查命令

```bash
lark-cli auth status     # 查看身份、token 有效性、过期时间、scope
lark-cli auth list       # 列出已登录 profile
```

已授权 scope 覆盖支撑所需全部能力：wiki 节点读取、Base 表/字段/记录读写、电子表格读写、文档导出、消息读取（写消息能力存在但**未获用户明确授权前不得代发 IM**）。

## 3. 同步脚本配置（scripts/sync/）

### 3.1 sync-config.json —— 唯一需要按环境修改的文件

| 字段 | 说明 | 换机时 |
|------|------|--------|
| `lark_cli_entry` | lark-cli run.js 绝对路径 | npm 全局路径变了就要改 |
| `git.repo` | 代码仓本地绝对路径 | 工作区换盘符/目录时改 |
| `git.branch / remote / web_url` | develop / origin / GitHub 地址 | 一般不动 |
| `faq.wiki_url / doc_id` | FAQ wiki 文档地址与 doc_id | 换 FAQ 文档时改 |
| `base.base_token / wiki_entry` | 项目管理一张表 Base | 换 Base 时改 |
| `base.tables[]` | 6 张表的 table_id 与缓存输出路径 | 一般不动 |
| `sheet.spreadsheet_token / wiki_url` | 现网问题个人跟踪电子表格 | 换表时改 |

全部表 ID、Base token、现网支撑记录电子表格 token 见 `config.json` → `ids`（写入/排查时按名取用，不要凭记忆手敲）。

### 3.2 sync-all.mjs —— 每日同步主脚本

五阶段顺序执行（**push 先推后拉**，保证缓存包含刚写入的记录）：

```
push  — tmp_base/pending/ 本地写队列 → 批量写飞书（唯一允许的飞书写操作，条目均经双确认入队）
git   — nexent 仓 develop fetch + pull --ff-only
faq   — FAQ wiki 文档 → tmp_base/Nexent平台部署FAQ-复刻.md（自动保护文件末尾「本地沉淀区」标记以下内容）
base  — 项目管理一张表 6 张表 → tmp_base/*.ndjson（含 manifest/fields 快照）
sheet — 现网支撑记录全部子表 → tmp_base/*.csv
最后自动重建 tmp_base/资源索引.md（状态、链接、队列、沉淀区计数、失败详情）
```

```bash
node scripts/sync/sync-all.mjs              # 全量同步
node scripts/sync/sync-all.mjs --only git,faq   # 只跑指定阶段（逗号分隔）
node scripts/sync/sync-all.mjs --push-dry-run   # 只打印将推送内容，不写飞书
```

也可双击 `scripts\sync\sync.cmd`（等价于全量同步 + pause）。脚本本身除 push 阶段外**只读**，不会写飞书。

- 运行日志：`scripts/sync/state/sync-YYYYMMDD.log`；累计状态：`scripts/sync/state/sync-state.json`；
- 每阶段独立容错：单项失败不影响其他资源，失败详情汇总在 `tmp_base/资源索引.md`；
- FAQ 的二进制附件（如 410MB 镜像 tar）不做本地缓存，按复刻文件中的占位说明从原文档获取。

### 3.3 table-write.mjs —— 表格本地写队列

逐单直写飞书太慢，所有表格写操作走「本地入队（毫秒级）→ 每日同步 push 阶段批量推送」：

```bash
# 新增记录（两道双确认通过后！未带 --confirm-note 会被拒绝）
node scripts/sync/table-write.mjs --op record --table-id <3问题跟踪新表ID，见 config.json> \
  --json '{"问题描述":"...","问题局点":["华西医院"],"责任模块":["模型管理"],"优先级":["P1"],"问题发现版本":["v2.7.0"]}' \
  --confirm-note "双确认完成：内容确认+操作允许（2026-10-21）"

# 支撑记录表追加行（7 列：A=时间 B=问题来源人 C=问题局点 D=事件 E=结论 F=是否闭环 G=修复难度，
# 列结构详见技能包 references/templates.md 第五节；子表 sheet_id 变动时用 sheets +workbook-info 查询）
node scripts/sync/table-write.mjs --op sheet-append --sheet-id 081adc \
  --row '["2026年10月28日","张三","华西","现象一句话","结论一句话","否","易"]' \
  --confirm-note "..."

node scripts/sync/table-write.mjs --list          # 查看待推送（--all 含已推送）
node scripts/sync/table-write.mjs --cancel <id>   # 撤销（仅「待推送」可撤）
```

推送结果（record_id / 失败原因）写回 `tmp_base/pending/` 各文件并汇总到 `tmp_base/资源索引.md`「本地待推送队列」。仅紧急需即时落表才用 `lark-cli base +record-upsert ... --dry-run` 预览后真写（仍需双确认）。字段规范见技能包 `references/templates.md` 第四节。

## 4. 自动化任务设置（agent 平台）

### 4.1 现有自动化

| 项 | 值 |
|----|----|
| 名称 | Nexent 支撑资源每日同步（每天 08:30） |
| 计划 | cron `30 8 * * *`（本地时区，每天 08:30，长期重复） |
| 机制 | agent 平台持久自动化，独立于会话运行 |
| 当前状态 | active，已正常运行（今日 08:32 完成最近一次，11/11 项成功） |

自动化每次运行做三件事：

1. 运行 `node "D:/projects/feishu/scripts/sync/sync-all.mjs"`（含 push 队列推送 + 四类只读同步 + 重建 tmp_base/资源索引.md）；
2. 读取 `tmp_base/资源索引.md` 汇报：全部成功时报关键版本（FAQ revision、问题跟踪表 rev、git HEAD、拉取提交数、推送结果）；有失败项逐项列出原因与处理办法（授权失效 → 提示 `lark-cli auth login` 重授权后手动重跑）；
3. 安全约束：除脚本内置 push 外不得调用任何飞书写命令；不改 FAQ 沉淀区；待推送条目 push_attempts ≥3 时提醒人工处理。

### 4.2 如何重建（换机 / 误删后）

在 agent 平台会话中直接说「**每天 08:30 创建自动化**」并把下面 prompt 原文给它（或自己组织语言，要点一致即可）：

```text
执行 Nexent 支撑资源每日同步与待推送队列推送：

1. 用 Bash 运行：node "D:/projects/feishu/scripts/sync/sync-all.mjs"（超时给足 10 分钟）。
   脚本第一阶段（push）会把 tmp_base/pending/ 中已双确认入队的表格写操作批量写入飞书
   （这是本次唯一允许的飞书写操作，内容均为支撑流程⑥双确认后入队的既定写入），
   随后执行只读同步（FAQ wiki 文档、项目管理一张表 6 张 Base 表、现网支撑记录电子表格、
   nexent 仓 develop fast-forward），最后自动更新 D:\projects\feishu\tmp_base\资源索引.md。
2. 读取 D:\projects\feishu\tmp_base\资源索引.md 的「总体状态」行、表格与「本地待推送队列」一节：
   全部成功时用两三句话汇报关键版本及队列推送结果，不必逐项罗列；
   若有失败项或飞书授权显示已失效，逐项列出失败资源与错误原因，并给出处理办法——
   飞书授权失效时告知用户在终端运行 lark-cli auth login 重新授权后手动重跑同步。
3. 除脚本内置 push 阶段外，不得调用任何其他飞书写命令（如手动 base +record-upsert）；
   不得修改 FAQ 沉淀区（文件末尾标记以下内容）。
   若某条待推送条目 push_attempts 已 ≥3（见 tmp_base/pending/ 各 JSON 文件），
   在汇报中单独列出并提醒人工处理。
```

⚠️ prompt 中硬编码了工作区绝对路径——**换机后路径变了必须重建自动化**，不能只改 sync-config.json。最新版 prompt 以仓库根 README.md 步骤 7 为准。

### 4.3 管理与兜底

- 查看/修改/暂停：对 agent 平台说「列出我的自动化 / 暂停每日同步 / 改到每天 09:00」，或在平台的自动化管理页面操作；
- 兜底：自动化没跑（关机、agent 平台未运行）不会丢数据——双击 `scripts\sync\sync.cmd` 或手动跑一遍全量同步即可补上；连续没跑只影响缓存新鲜度与队列推送延迟，飞书侧数据不受影响；
- 验证最近一次运行结果：看 `tmp_base/资源索引.md` 生成时间与「总体状态」行。

## 8. 故障排查速查

| 症状 | 原因 | 处理 |
|------|------|------|
| 资源索引标「飞书授权已失效」 | user refresh token 超过 7 天未用 | 终端 `lark-cli auth login` 重授权 → 手动重跑同步 |
| git 阶段失败：非快进 | 本地仓有游离改动/被切分支 | `git -C nexent stash` 或确认后 `reset --hard origin/develop` |
| 脚本报「找不到 lark-cli 入口」 | npm 全局路径变化 | 改 `sync-config.json` 的 `lark_cli_entry`，或设环境变量 `LARK_CLI_ENTRY` |
| push 连续失败（attempts ≥3） | 字段值不合法 / 权限变化 | 看 pending 文件 `last_error`，修正字段后重新入队或人工直写 |
| 某资源 ❌ 其他正常 | 单项容错，常见为远端文档/表权限变化 | 看 `tmp_base/资源索引.md` 失败详情 + 当日 state 日志，找资源所有者开权限 |
